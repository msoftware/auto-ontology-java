**Aggregation**
- Never use FILTER (WHERE ...) on aggregates — it is not supported in all dialects. Use CASE WHEN inside aggregates instead: COUNT(CASE WHEN condition THEN 1 END) or SUM(CASE WHEN condition THEN 1 ELSE 0 END).
- If business categories are specified, use CASE WHEN to classify.
- A condition on an aggregated value belongs in HAVING, not WHERE. When the question qualifies an entity by a total, average or count taken over that entity's rows ('customers whose consumption is under 30000', 'patients with two or more abnormal tests'), group by the entity and compare the aggregate in HAVING. A WHERE predicate tests one row at a time, before grouping, and answers a different question.
- Integer division truncates. Cast to REAL before dividing wherever the result can be fractional — CAST(SUM(x) AS REAL) / COUNT(y) — including inside HAVING and before scaling a ratio by 100.
